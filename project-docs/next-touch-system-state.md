## Contact Brief modal (rebuilt 2026-08-26 — replaces the toggleRes/.resources panel entirely, required on every Next Touch card, new or existing)

Adam reported the old Contact Brief popup ("the toggleRes panel described above through 2026-08-26") wasn't functioning correctly and asked for every name anywhere in Next Touch to be clickable and open a real popup with a Call Coach section, an expand/collapse full profile, and a clear close/back control — applied globally, not per-card. The toggle-panel pattern was fully replaced with a shared modal:

1. **One shared modal, driven by one data blob.** The dashboard has `#briefOverlay`/`#briefModal` markup once, near the end of the body — a fixed overlay + centered panel with a priority badge, name/business/email header, a meta-grid (last contact / upcoming meeting / follow-up signal), three `<details class="modal-section">` blocks (Conversation history & notes, Recommended next action, Call Coach), and a resources row (Full Contact Brief button if `briefUrl` is set, Reading the Tape button if `readingTapeUrl` is set, Call Verbiage Field Guide always). All 20 tracked contacts' data — `name/business/email/priority/tier/signal/lastContact/upcoming/notes/action/briefUrl/coach` (+ `readingTapeUrl` where applicable) — lives in one `<script type="application/json" id="contacts-data">` blob at the end of the page. `openBrief(slug)` reads that blob and populates the modal; `closeBrief()` hides it. Escape key, clicking outside the panel, and an explicit Close button all call `closeBrief()`.
2. **Every name is clickable, everywhere.** Main dashboard cards (`id="c-<slug>"`, name wrapped in `onclick="openBrief('<slug>')"`), the This Week section's name spans, and any other place a tracked contact's name appears on the page all call the same `openBrief(slug)` — never a separate per-location implementation. When adding a NEW contact, add one entry to `contacts-data` (including its own `coach` object — see next point) and wire its name element the same way; don't invent new modal markup per contact.
3. **Call Coach is standard, not a Nathan-only pilot (decided 2026-08-26 — trial complete, rolled out to everyone).** Every contact's `coach` object holds a short situation summary plus a handful of talking points (`[label, verbiage]` pairs) grounded in that contact's real notes, objections, and transcript, tailored from the Call Verbiage Field Guide and, where one exists, that contact's own "Reading the Tape"-style review — never a generic script. A contact with genuinely no coachable signal yet (e.g. no call has happened) can have `coach: null` with a one-line `coachSkipNote` explaining why, rather than a fabricated section. This applies to all 20 tracked contacts via the modal now, and is required going forward for every new contact — see the Next Touch sync trigger's Step 1(h).
4. **Cross-artifact linking (Pipeline Pulse, Daily Priorities → Next Touch).** Next Touch, Pipeline Pulse, and Daily Priorities are three separate published Artifacts on separate origins with no shared live DOM/JS state, so a name on Pipeline Pulse or Daily Priorities cannot pop Next Touch's modal in place. The honest, working approximation: names on those two pages link out (`target="_blank"`) to `https://claude.ai/code/artifact/c2f940ca-0052-4c5c-8af8-50dda88f49e3#c-<slug>` — Next Touch's own hash-based deep-link auto-opens that contact's modal on load (via `location.hash` + a short `setTimeout`). Pipeline Pulse computes `by_email`/`by_biz` slug-matching maps against Next Touch's contact list for this (see its own header link and `.nt-name-link` styling); Daily Priorities wraps its own name mentions the same way. **Tell Adam plainly if he asks why clicking a name on Pipeline Pulse doesn't pop an inline modal the way Next Touch's own names do** — it opens Next Touch in a new tab already scrolled to and showing that contact's brief, which is the closest equivalent achievable across separate artifacts, not a limitation to paper over.
5. **Full profile expand/collapse.** The "Conversation history & notes" `<details>` block is where fuller profile content (needs/pain points, objections, goals, buying signals, commitments, next steps) lives when available — it expands/collapses independently of the other two sections, same `<details>` pattern used throughout the system.
6. **Priority quick-nav** (unchanged from the prior pass): the four `.stat` boxes at the top (High/Medium/Low/No action) are each wrapped in an `<a href="#group-X">` — clicking one jumps straight to that priority group.

Preserve this pattern for every card the hourly sync touches or creates going forward (see the sync trigger's Step 1(g)/(h) and Step 4, already updated to reference it) — copy the exact CSS classes and the `openBrief`/`closeBrief` JS rather than inventing new ones. **Never rebuild a `toggleRes`/`.resources` panel — that pattern is retired.**

## Behavior rules (confirmed with Adam)

- **Notes auto-update on inbound email:** when a tracked contact emails in, re-read the thread, update their contact-brief page and their Next Touch card. Explicitly flag if the message signals: wants to cancel / no longer interested, found another solution, is asking follow-up questions, provided new information relevant to the next step, or anything else that changes the recommended next action.
- **Auto re-prioritize on response:** a contact who replies moves to the top of that day's priority list. State the reason in plain language (e.g. "Replied to follow-up email, asking about pricing") — never just re-rank silently.
- **Quick-reply drafts, not auto-send:** when generating a suggested reply, create it as a Gmail draft (`create_draft`) addressed and ready to go. Never send automatically. This was an explicit decision — no exceptions without Adam saying so directly.
- **Daily priority engine:** every run should be able to answer "what should Adam work on right now, and why" by combining (a) unanswered/new client responses, (b) today's and tomorrow's meetings with prep notes, and (c) the Apollo tiers above. Sort: tier A/urgent responses first, then by how overdue the follow-up is relative to that contact's stage — never a flat "X days = overdue" rule.
- **Salesforce:** still no live API access (org OAuth policy blocked, pending admin). Contact-brief content is what gets pasted into Salesforce or relayed via the Pipeline Pulse chat — this doesn't change until Adam reports the block is lifted.
- **Flag edits, don't silently overwrite:** whenever a run changes existing content on a contact's brief page (not just appending a new call section), it must be visibly flagged — both an entry in that page's "Update log" section (timestamp + one-line reason, e.g. "Aug 26, 9:14 AM — sequence step changed from 'Price consideration' to 'Awaiting decision': client emailed asking to confirm the annual price before signing") and, where the changed content itself is still shown, a short inline note on what it replaced and why. Never quietly replace a fact that was previously stated — old figures a client corrected (a runrate, a headcount, etc.) fall under this the same as sequence/priority changes.
- **Consolidate call history — never fragment:** a contact gets exactly ONE brief page, permanently. When a new transcript lands for a contact who already has a page, do not create a second page or a standalone note. Follow the "CALL HISTORY CONVENTION" comment on the contact-brief template (above the "Previous calls" section): move the current "Last call" section's content into a condensed, dated entry under "Previous calls," replace "Last call" with the new call's notes, merge new/changed facts into the single "Full business profile" table (flagging via the Update Log rule if something changed rather than just being added), and regenerate "Before your next call" from the newest call's open items — not the older ones. Opening the page should always show the complete, current relationship in one place, not fragments of it across multiple notes.
- **End-of-day missing-notes flag:** if a tracked meeting has ended but Gemini's notes still haven't landed by the end of the day (check: current time is after 6 PM in Adam's local time, Mountain Time), stop waiting silently. Add a clearly visible "⚠ Missing notes" flag for that contact on the Next Touch dashboard (don't bury it in the state doc's run log alone) so Adam sees at a glance which calls still need a transcript chased down.
